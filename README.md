# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

### Данные

##### Интерфейсы данных

**IProduct** — описывает структуру данных товара.

```typescript
    interface IProduct {
    id: string;
    title: string;
    image: string;
    category: string;
    price: number | null;
    description: string;
    }
```
Унифицированное описание товара для передачи и хранения данных в приложении.

**IBuyer** — описывает структуру данных покупателя.

```typescript
    type TPayment = 'card' | 'cash' | '';

    interface IBuyer {
    payment: TPayment;
    address: string;
    email: string;
    phone: string;
    }
```
Описание данных покупателя, необходимых для оформления заказа.

### Модели данных

#### Каталог товаров (Catalog)

Отвечает за хранение полного массива товаров и текущего выбранного товара для отображения карточки. Обеспечивает методы для получения и сохранения данных каталога и отдельного товара.

**Конструктор:**

`constructor()` — не принимает параметров, инициализирует внутренние поля пустыми значениями.

**Поля класса:**

`products: IProduct` — массив всех товаров каталога. Хранит полный список товаров, доступных для покупки.
`selectedProduct: IProduct | null` — выбранный товар. Хранит данные товара, карточка которого в данный момент отображается пользователю.

**Методы класса:**

`setProducts(products: IProduct): void` — принимает массив товаров, сохраняет его в поле products.
`getProducts(): IProduct` — возвращает массив всех товаров из поля products.
`getProductById(id: string): IProduct | undefined` — принимает id товара, возвращает товар из массива products с соответствующим id или undefined, если товар не найден.
`setSelectedProduct(product: IProduct): void` — принимает объект товара, сохраняет его в поле selectedProduct.
`getSelectedProduct(): IProduct | null` — возвращает текущий выбранный товар из поля selectedProduct.

#### Корзина (Cart)

Отвечает за хранение списка товаров в корзине, расчет итоговой стоимости и количества товаров, а также проверку наличия товаров.

**Конструктор:**

`constructor()` — не принимает параметров, инициализирует массив корзины пустым.

**Поля класса:**

`items: IProduct` — массив товаров в корзине. Хранит список товаров, добавленных пользователем.

**Методы класса:**

`getItems(): IProduct` — возвращает массив товаров, находящихся в корзине.
`addItem(product: IProduct): void` — принимает товар, добавляет его в массив items.
`removeItem(product: IProduct): void` — принимает товар, удаляет из массива items первый элемент с совпадающим id.
`clear(): void` — очищает массив items, удаляя все товары из корзины.
`getTotalPrice(): number` — возвращает сумму стоимости всех товаров в корзине (сумма значений поля price, игнорируя null).
`getCount(): number` — возвращает количество товаров в массиве items.
`hasItem(id: string): boolean` — принимает id товара, возвращает true, если товар с таким id присутствует в массиве items, иначе false.

#### Покупатель (Buyer)

Обеспечивает частичное обновление полей, получение полного профиля и проверку корректности введенных данных.

**Конструктор:**

`constructor()` — не принимает параметров, инициализирует все поля пустыми строками или значением по умолчанию для payment.

**Поля класса:**

`payment: TPayment` — способ оплаты. Хранит выбранное значение: 'card', 'cash' или пустую строку.
`address: string` — адрес доставки. Хранит строку с адресом покупателя.
`email: string` — электронная почта. Хранит email-адрес покупателя.
`phone: string` — номер телефона. Хранит номер телефона покупателя.

**Методы класса:**

`setData(data: Partial<IBuyer>): void` — принимает объект с частичными данными покупателя (IBuyer с опциональными полями), обновляет только переданные поля, не затрагивая остальные.
`getData(): TBuyer` — возвращает объект со всеми текущими данными покупателя.
`clear(): void` — сбрасывает все поля класса в значения по умолчанию (пустые строки, пустая строка для payment).
`validate(): Record<keyof IBuyer, string> | {}` — выполняет валидацию всех полей. Проверяет, что каждое поле не является пустой строкой. Возвращает объект, где ключи соответствуют полям класса, а значения — текст ошибки для невалидных полей. Если поле валидно, оно отсутствует в возвращаемом объекте. Пример возвращаемого значения: { payment: 'Не выбран вид оплаты', email: 'Укажите емэйл' }.

### Слой коммуникации

#### Класс ApiService

Класс отвечает за взаимодействие с сервером «Веб-Ларёк»: получение каталога товаров и отправку заказа.

**Назначение:**
- Получение списка товаров с эндпоинта `/product/`.
- Отправка данных заказа на эндпоинт `/order/`.
- Преобразование и типизация входящих/исходящих данных без дублирования типов.

**Конструктор:**
`constructor(api: IApi)` — принимает экземпляр, реализующий интерфейс `IApi`.

**Поля класса:**
- `api: IApi` — экземпляр API-клиента для выполнения запросов.

**Методы класса:**

- `getProducts(): Promise<{ total: number; items: IProduct[] }>`  
  Выполняет GET-запрос на `/product/`. Возвращает объект с полями `total` (общее количество товаров) и `items` (массив товаров типа `IProduct`).

- `sendOrder(orderData: { buyer: IBuyer; items: IProduct[]; total: number }): Promise<{ id: string; total: number } | { error: string }>`  
  Отправляет POST-запрос на `/order/` с данными заказа: покупатель, список товаров и итоговая сумма.  
  Возвращает либо подтверждение заказа (`id`, `total`), либо объект с ошибкой (`error`).
